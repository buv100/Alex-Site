## 1. עקרונות יסוד

1. **SPEC קודם לקוד.** אם הדרישה משתנה — מעדכנים את `docs/SPEC.md` ואז את הקוד.
2. **אתר WEB קודם לאפליקציה.** אין לבנות native/PWA מלאה לפני ש־Phase 3 יציב.
3. **תקציב 0.** אין שירות בתשלום בלי אישור מפורש בכתב מהמפתח האחראי.
4. **Mobile-first בכל מקום** — האתר הציבורי נוח לטלפון.
5. **מודולריות ותיעוד.** כל מודול חדש מתועד בקצרה; אין "קסם" לא מתועד ב־`lib/`.
6. **אחידות.** אותם דפוסי שמות, אותה שפת UI לפי אזור, אותם רכיבי בסיס.
7. **סודיות כלי העבודה הפנימי.** אין לשתף / לתעד ב־GitHub / README / docs ציבוריים / UI ציבורי שום קישור כניסה, סיסמה, אסימון או הסבר שמגלה את הממשק הפנימי. פרטי תפעול רק מקומית בקבצים מוחרגים מ־git או ב־env בשרת.

## 2. מקור אמת ומעקב שינויים

| סוג שינוי | חובה |
|-----------|------|
| פיצ׳ר חדש / שינוי ביזנס לוגיק | עדכון SPEC + מימוש |
| באג / ריפקטור פנימי בלי שינוי התנהגות | קומיט ברור; בלי עדכון SPEC |
| שינוי משפטי / נגישות / פרטיות | עדכון SPEC + PROJECT_RULES אם צריך |
| הוספת תלות / שירות חיצוני | תיעוד ב־SPEC (§ טכנולוגיות) + env ב־README |

### Git
- ענפים קצרים לפי פיצ׳ר (`feat/...`, `fix/...`).
- קומיטים באנגלית, ממוקדים ב־"למה".
- **אסור** קומיט של `.env`, מפתחות, סיסמאות, dumps עם PII.
- לא לדחוף ל־`main` ישירות אם יש תהליך PR — העדפה: PR קטן וקריא.
- לא `--force` על main, לא `--no-verify`, אלא אם המפתח ביקש במפורש.

## 6. Definition of Done (לכל פיצ׳ר)

לפני סימון "הושלם":

1. עובד במובייל (רוחב ~390px לפחות) בנוחות.
2. תואם לכללי הביזנס ב־SPEC (§7).
3. **אין דליפת שדות פנימיים** ב־API/HTML ציבורי.
4. נגישות בסיסית: מקלדת, focus, labels, alt, ניגודיות סבירה.
5. טפסים עם צ׳קבוקס פרטיות כשאוספים PII.
6. RTL תקין בעברית.
8. אין סודות בקוד.
9. עדכון docs אם השתנתה התנהגות.

---

## 7. חוקי נגישות (חובה בכל שינוי UI)

יישום לפי **ת״י 5568 / WCAG 2.0 AA** (ראה SPEC §11):

1. לא לפרסם תמונה בלי `alt` משמעותי (דקורטיבי → `alt=""` במודע).
2. כל קלט עם `<label>` מקושר.
3. ניווט מקלדת + `focus-visible`.
4. Skip link לדפים ציבוריים.
5. לא מידע בצבע בלבד.
6. כפתורים ולינקים סמנטיים.
7. מודאלים/תפריטים: trap focus וסגירה ב־Escape כשמתאים.
8. הצהרת נגישות תמיד זמינה בפוטר.
9. תוסף צד־שלישי לנגישות **אינו** תחליף להנגשה בקוד.

בדיקה מינימלית לפני merge משמעותי: מקלדת ידנית + axe או Lighthouse Accessibility.

## 8. חוקי פרטיות (חובה)

לפי **חוק הגנת הפרטיות + תיקון 13** (ראה SPEC §12):

1. אין טופס ליד/הרשמה בלי מדיניות פרטיות נגישה + צ׳קבוקס הסכמה **לא** מסומן מראש.
2. אין חיבור אנליטיקס/פיקסל לא-חיוני בלי מנגנון הסכמה לעוגיות.
3. מינימום נתונים — לא לשמור "ליתר ביטחון".
4. שדות בעל נכס / מחיר מינימום / כתובת מדויקת — לא בציבור.
5. בקשות מחיקה/עיון — תהליך מתועד במדיניות (טיפול ידני ב־v1 מספיק).

**הבהרה:** טיוטות משפטיות בקוד אינן ייעוץ משפטי; מומלץ אישור עו״ד לפני לידים אמיתיים.

## 9. אבטחה

| אזור | רמה | כללים |
|------|-----|--------|
| כתיבת נתונים | גבוהה | הרשאה בשרת לכל mutation; סודות לא בקומיט |
| משתמש ציבורי | בסיסית | hash לסיסמאות, ולידציה, הגבלת גודל העלאות |
| API ציבורי | — | allowlist של שדות Property; לעולם לא `owner*`, `internalNotes`, `exactAddress`, `minPriceNegotiable` |

- סיסמאות רק כ־hash.
- סודות רק ב־env / secrets של Vercel.
- אחרי שינוי מודל נתונים — בודקים שאין leak ב־Network tab בדף נכס.

## 10. עיצוב

1. מוגדרים CSS variables למותג (רקע, משטחים, טקסט, אקסנט, רדיוס, צל עדין).
2. כיוון: יוקרתי, כהה-מתון, פשוט — לא גנרי.
3. **אסור** כברירת מחדל של הפרויקט:
   - ערכות סגול/אינדיגו AI נפוצות
   - cream + serif + terracotta קלישאי
   - broadsheet צפוף עם קווים דקים בלבד
4. Hero: מותג חזק; בלי כרטיסיות ב־hero; בלי באדג׳ים צפים על מדיה.
5. כרטיסיות רק כשצריך אינטראקציה/הבנה — לא כקישוט.
6. תנועה: 2–3 מושכלות; לא רעש.
7. פונטים אקספרסיביים (לא Inter/Roboto/Arial כזהות המותג).

## 11. נתונים וביזנס לוגיק בקוד

חייב להתאים ל־SPEC §7:

- פרסום רק ע״י בעל העסק; `published` רק עם ≥1 תמונה.
- מחיר חסר → `"צור קשר לבירור"`.
- כתובת ציבורית בלי מספר בניין/דירה.
- מיון רשימה פעילה: אקראי.
- Soft-delete + ארכיון `sold`/`rented`.
- ליד מנכס שומר snapshot של כותרת + קישור + `propertyId`.

שינוי בכלל מאלה = עדכון SPEC קודם.
