## 1. מטרת המערכת ומדדי הצלחה

### 1.1 חזון
אתר פשוט ונקי למותג האישי **אלכס נכסים**: הצגת דירות מגורים בירושלים (מכירה ושכירות), יצירת קשר נוחה עם אלכס, וניהול עצמאי של הנכסים והפניות — במיוחד מטלפון (אלכס עובד רק מדפדפן במובייל).

### 1.2 מטרות עסקיות (לפי עדיפות)
1. **נוחות לרשת הקיימת** של אלכס — במקום שיחות אינסופיות ושליחת תמונות/פרטים ידנית.
2. **נוחות לאלכס** — דף ניהול mobile-first לפרסום נכסים, מעקב לידים וסטטיסטיקות.
3. **לידים** — פנייה לנכס ספציפי, פנייה כללית, ולידים ממוכרים שרוצים לפרסם נכס.
4. **חשיפה לקהל חדש** — משנית בשלב זה; לא דוחפת SEO אגרסיבי או פרסום ממומן.

### 1.3 מדדי הצלחה (KPI)
| KPI | הגדרה |
|-----|--------|
| לידים חדשים | מספר פניות טופס / שבוע |
| המרות WhatsApp | לחיצות על כפתור WhatsApp מנכס |
| זמן פרסום נכס | מאלכס מתחיל העלאה עד `published` (יעד: נוח במובייל, דקות בודדות) |
| שימוש במועדפים | משתמשים רשומים ששומרים נכסים |
| שביעות רצון תפעולית | אלכס מצליח לנהל לבד מהטלפון בלי עזרה יומיומית |

### 1.4 מה האתר **אינו**
- לא מתחרה ליד2 / מדלן (אין חיפוש טקסט חופשי מאגר ענק).
- לא פלטפורמת תיווך מרובת מתווכים.
- לא אפליקציה native בשלב זה.
- לא CMS לתוכן שיווקי דינמי (טקסטים סטטיים בקוד).

## 3. תרחישי משתמש (User Stories + Flows)

### 3.1 מבקר — גלישה ופנייה לנכס
1. נכנס לדף הבית → רואה מותג, הסבר על אלכס, CTA לנכסים / יצירת קשר.
2. עובר לרשימת נכסים → מסנן לפי שכונה / מחיר / חדרים / סוג עסקה / תגיות.
3. נכנס לדף נכס → רואה תמונות ופרטים (בלי כתובת מדויקת).
4. בוחר:
   - **WhatsApp:** פותח צ׳אט עם הודעה מוכנה על הנכס.
   - **טופס:** שם + טלפון (+ הסכמת פרטיות) → ליד נשמר + התראה לאלכס.

### 3.2 מבקר — פנייה כללית
1. "צור קשר" → טופס שם + טלפון / או קישור WhatsApp כללי / `tel:`.
2. ליד מסוג `general` בלי `propertyId`.

### 3.3 מוכר פוטנציאלי
1. "יש לי נכס למכירה/השכרה" → טופס שם, טלפון, תיאור קצר, סוג עסקה רצוי.
2. ליד מסוג `seller` → אלכס חוזר ידנית.

### 3.4 משתמש רשום — מועדפים
1. הרשמה מהירה (פחות מחצי דקה) → חשבון.
2. שמירת נכס למועדפים / הסרה.
3. צפייה ברשימת מועדפים מהפרופיל.

### 3.5 אלכס — פרסום נכס מהטלפון
1. התחברות אדמין מאובטחת.
2. "נכס חדש" → מילוי שדות ציבוריים + פנימיים → העלאת תמונות מהגלריה.
3. שמירה כ־`draft` → תצוגה מקדימה → `published`.
4. מאוחר יותר: סימון `sold` / `rented` → מעבר לארכיון "הנכסים שמכרנו".

### 3.6 אלכס — טיפול בליד
1. דשבורד / תיבת לידים → רואה ליד חדש (כולל קישור לנכס אם רלוונטי).
2. מעדכן סטטוס: `new` → `in_progress` → `closed`.
3. יוצר קשר מחוץ לאתר (שיחה / WhatsApp) — **ישירות מכפתורים באדמין**.

### 3.7 אלכס — שפה באדמין
1. מחליף ממשק בין עברית לרוסית בכל מסכי הניהול.

### 3.8 נוחות ללקוחות קיימים (יעד מוצר)
האתר נועד גם לרשת הקיימת של אלכס — לא רק לגולשים חדשים:

| יכולת | למי | סטטוס |
|--------|-----|--------|
| שליחת קישור נכס בוואטסאפ (טקסט מוכן) | אלכס → לקוח | v1 (ציבורי + אדמין) |
| מועדפים + הרשמה מהירה | לקוח חוזר | v1 |
| סינון שכונה/מחיר/חדרים בלי חיפוש חופשי | לקוח | v1 |
| ארכיון "הנכסים שמכרנו" (אמון) | לקוח | v1 |
| כפתור התקשר / וואטסאפ מכל נכס | לקוח | v1 |
| שיתוף נכס מהאדמין ללקוח ספציפי (העתקת קישור / WA) | אלכס | חיזוק אדמין |
| שמירת העדפות סינון (local) | לקוח | Phase מאוחר |
| התראת וואטסאפ ללקוח על נכס חדש מתאים | אלכס שולח ידנית / בעתיד בוט מסייע | לא אוטומציה מלאה ב־v1 |
| בוט צ׳אט לשאלות על נכסים ועל אלכס | לקוח | ראה §3.9 — מתוכנן |

### 3.9 בוט צ׳אט (מתוכנן — לא v1 מיידי)
**מטרה:** מענה מיידי בעברית לשאלות נפוצות על נכסים פעילים ועל אלכס, ולהפחית שיחות חוזרות — בלי להחליף את אלכס בעסקאות.

**כללי ברזל:**
1. עונה רק על מידע **ציבורי** (אותם שדות כמו באתר). אסור לחשוף `owner*`, `exactAddress`, `internalNotes`, `minPriceNegotiable`.
2. על מחיר חסר → מפנה ל"צור קשר לבירור" / וואטסאפ לאלכס.
3. שאלות מחוץ להיקף / מו״מ → הסלמה ל־WhatsApp / טופס ליד.
4. עברית בלבד בצד הציבורי.
5. תקציב: **חינמי בלבד** אלא אם יאושר מפורשות שירות בתשלום.
6. פרטיות: לא לשמור שיחות עם PII בלי הסכמה; עדיף שיחה אפיזודית + לוג אדמין אגרגטיבי בלבד (אם בכלל).

**גישת מימוש מוצעת (שלבים):**
| שלב | תוכן | הערות |
|-----|------|--------|
| A | FAQ קבוע על אלכס + קישורי נכסים לפי מסננים פשוטים (שכונה / מכירה-שכירות) | בלי LLM, חינם |
| B | Retrieval על תיאורי נכסים מפורסמים + תשובות מובנות | עדיין ללא עלות API |
| C | LLM בשכבת free-tier (רק אם יאושר) מעל אותם מקורות | עם הגבלת קצב + disclaimer |

**מיקום UI:** כפתור צ׳אט צף באתר הציבורי (לא חוסם נגישות; ניתן לסגירה במקלדת).

**אדמין (עתידי):** צפייה בשאלות נפוצות / כיבוי בוט / עדכון FAQ — לא חובה ב־MVP של הבוט.

## 5. UX / UI — עקרונות עיצוב

### 5.1 כיוון ויזואלי
- יוקרתי, פשוט, ייחודי — **לא** מראה AI גנרי.
- צבעים כהים יחסית אך לא קיצוניים (רקע כהה-מתון, טקסט בהיר, אקסנט חם/זהוב או כחול-עמוק — יוגדר ב־CSS variables).
- טיפוגרפיה אקספרסיבית (לא Inter/Roboto/Arial כברירת מחדל).
- תמונות נכסים אמיתיות בלבד (אלכס מעלה).

### 5.2 דף הבית — viewport ראשון
חייב לכלול:
1. שם המותג **אלכס נכסים** כסיגנל hero.
2. הסבר קצר על אלכס ולמה כדאי לעבוד איתו.
3. קבוצת CTA (למשל: לצפייה בנכסים / צור קשר).
4. עוגן ויזואלי (תמונת אלכס / אווירת נדל״ן בירושלים) — full-bleed לפי כללי העיצוב של הפרויקט.

**לא** ב־viewport הראשון: סטטיסטיקות, רשימות אירועים, כרטיסיות מרובות, באנרים צפים.

### 5.3 Mobile-first
- כל המסכים הציבוריים והאדמין מותאמים לטלפון קודם.
- אדמין: כפתורים גדולים, טפסים במסך אחד לגלילה, העלאת תמונות מגלריית הטלפון, שמירה מהירה.

### 5.4 שיתוף
- כפתור שיתוף WhatsApp בכל דף נכס (לינק + טקסט קצר).

### 5.5 שפות
| אזור | שפה |
|------|-----|
| אתר ציבורי | עברית בלבד |
| אדמין | עברית + רוסית (החלפת שפה בממשק) |
| אנגלית | אין באתר הציבורי |

## 7. ביזנס לוגיק וכללים

### 7.1 מחזור חיים של נכס
```
draft → (preview) → published → sold | rented → archive
                              ↘ soft-delete (deletedAt)
```

| סטטוס | נראה בציבור | הערות |
|--------|-------------|--------|
| `draft` | לא | טיוטה; רק אדמין |
| `published` | כן ברשימה הראשית | חייב ≥1 תמונה |
| `sold` / `rented` | בארכיון "הנכסים שמכרנו" | לא ברשימה הראשית |
| soft-deleted | לא | ניתן לשחזור מאדמין |

### 7.2 כללי פרסום
1. רק אלכס יכול לפרסם / לשנות סטטוס ל־`published`.
2. בלי תמונה אחת לפחות → **אין** מעבר ל־`published`.
3. מחיר ריק/null → תצוגה: **"צור קשר לבירור"** (לא ₪0).
4. כתובת ציבורית: עיר + שכונה + (אופציונלי) שם רחוב — **בלי** מספר בניין/דירה.
5. מיקוח על מחיר — רק דרך אלכס (מחוץ לאתר / הודעה).
6. תגיות `isOpportunity` / `isExclusive` מוצגות כתגים ויזואליים.
7. מיון ברשימת נכסים פעילים: **אקראי בכל טעינת עמוד** (אין ברירת מחדל של חדש ביותר).
8. אין הגבלת מספר נכסים פעילים (צפי: 5–15).

### 7.3 סינון (בלי חיפוש טקסט)
מסננים נתמכים:
- סוג עסקה (`sale` / `rent`)
- שכונה בירושלים
- טווח מחיר
- מספר חדרים
- שטח (אופציונלי)
- תג הזדמנות / בלעדיות
- (אופציונלי) מעלית / חניה / מרפסת

### 7.4 פניות
| סוג | מקור | שמירה ב־DB | התראה לאלכס |
|-----|------|------------|-------------|
| נכס ספציפי | WhatsApp prefill | אופציונלי (לחיצה) | ההודעה מגיעה בוואטסאפ |
| נכס ספציפי | טופס | כן + `propertyId` | אימייל ו/או WhatsApp |
| כללי | טופס / WhatsApp | כן אם טופס | כנ״ל |
| מוכר | טופס `/sell` | כן `seller` | כנ״ל |

**אין** תשובה אוטומטית לפונה ב־MVP. **אין** CAPTCHA ב־MVP (אפשר rate-limit בסיסי בשרת).

### 7.5 תבנית הודעת WhatsApp לנכס
```
שלום אלכס, אני מעוניין/ת בנכס: {title}
שכונה: {neighborhood}
קישור: {url}
```

מספר היעד: מספר WhatsApp הפרטי של אלכס (יועבר ב־DATA_CHECKLIST) דרך `https://wa.me/{number}?text=...`.

### 7.6 מועדפים
- דורשים משתמש מחובר.
- שמירה ב־DB לפי `userId` + `propertyId`.
- נכס שנמחק/לא פעיל: מוצג כלא זמין או מוסר אוטומטית.

### 8.1 עקרונות
- **Mobile-first מוחלט** — אלכס עובד רק מטלפון בדפדפן.

### 8.3 עורך תוכן

### 8.4 תוכן סטטי באתר

## 10. אבטחה

### 10.1 אדמין (מחמיר)
- משתמש יחיד בלבד.
- סיסמה חזקה מ־env (`ADMIN_PASSWORD` / hash); **לא** סיסמת דמו בפרודקשן.
- Session ב־httpOnly + Secure + SameSite (Auth.js).
- **שער כניסה סודי:** `ADMIN_ENTRY_SECRET` — בלי `?access=…` תקף (או עוגיית שער) נתיבי `/admin` מופנים לדף הבית כאילו אינם קיימים.
- **אין לפרסם** קישור ניהול / סיסמאות / `access` ב־GitHub, README או פוטר ציבורי.
- Rate-limit על `/admin/login` (יעד; מינימום — סיסמה חזקה + שער).
- כל נתיבי `/admin/*` ו־API כתיבה מוגנים בשרת (לא רק UI).
- אין חשיפת שדות `owner*` / `internal*` / `exactAddress` / `minPriceNegotiable` ב־API ציבורי — **allowlist** בשכבת ה־DTO.

### 10.2 משתמשים ציבוריים (קל)
- הרשמה פשוטה; אין MFA.
- סיסמאות ב־hash בכל זאת.
- הגנה בסיסית מפני enumeration קיצוני — לא קריטי כמותית ב־MVP.

### 10.3 כללי
- HTTPS בכל מקום (Vercel).
- אין סודות ב־git.
- העלאת תמונות: סוגי קבצים מוגבלים (jpg/png/webp), מגבלת גודל.
- ולידציה בשרת לכל קלט.
